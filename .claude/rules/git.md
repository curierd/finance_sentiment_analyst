# 代码变更与远端同步的安全规则

## 1. 代码提交限制（Commit & Push）

**绝对禁止** Claude 在未经用户明确许可的情况下执行任何会导致代码提交到版本控制系统的操作。

- 禁止自动运行 `git commit`。
- 禁止自动运行 `git push`。
- 禁止自动运行 `git merge`、`git rebase` 或任何会改写提交历史的命令。
- 禁止在未获得用户确认前，使用 `-f` / `--force` 等强制推送选项。
- 禁止在提交信息中加入'Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>'

**许可流程**：
- 若你需要提交代码，**必须先列出**将要提交的所有变更文件，并用自然语言向用户解释本次提交的目的和内容。
- 然后**必须询问**：“是否允许我执行 `git commit` 和 `git push`？”
- **只有**在用户给出明确肯定答复（例如“可以”、“允许”、“执行”）后，你才能执行相应的 Git 命令。

## 2. 远端代码拉取限制（Pull / Fetch）

**绝对禁止** Claude 在未经用户明确许可的情况下主动拉取远端代码。

- 禁止自动运行 `git pull`。
- 禁止自动运行 `git fetch`（除非用户事前授权你定期检查更新）。
- 禁止自动运行 `git clone` 或从远端仓库下载新代码。

**许可流程**：
- 若你需要获取远端最新的代码（例如为了合并或解决冲突），**必须先**向用户说明原因：“我需要拉取远端更新来解决你提到的合并问题 / 获取团队最新提交。”
- 然后**必须询问**：“是否允许我执行 `git pull`（或 `git fetch`）？”
- **只有**在用户给出明确肯定答复后，你才能执行相应的 Git 命令。

## 3. 例外情况（仅限用户预先授权）

- 如果用户在项目规则或会话开始前已**书面写明**“允许 Claude 自动执行 `git fetch`（但不允许 pull/commit/push）”，则 `git fetch` 可以在无需逐次询问的情况下执行。
- 任何其他例外必须由用户在对话中逐次授权。

## 4. 违规后果

- 若你（Claude）在未获许可的情况下尝试执行以上禁止操作，用户有权立即终止对话，并重置你的系统指令。
- 你的行为应以“最小权限”为原则，宁可多问一句，也绝不擅自改动代码仓库或远端同步状态。
